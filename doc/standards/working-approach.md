# Working Approach

- Understand the existing behavior, relevant code, and architectural intent before making changes.
- Solve the underlying problem rather than treating symptoms.
- For significant changes, consider the ideal end-state before choosing an implementation path. Deliver that design incrementally where practical.
- Keep changes focused, but allow necessary refactoring when it produces a more coherent result.
- Preserve existing contracts unless changing them is intentional.
- Avoid unrelated changes, unnecessary dependencies, and speculative infrastructure.
